# 应用状态机地图

这份地图记录应用自己拥有或跨系统拼接的状态流。状态可能存在数据库字段、时间戳、队列和游标里，也可能散在几个 React state、ref 和异步回调里。范围覆盖 Web、API、CLI、Worker 和发布；独立的展开、悬停、复制提示等交互留给组件，第三方 SDK 内部状态以 SDK 为准。

排查时先找到**权威状态**，再看哪一次操作有权写它。HTTP 请求成功、对象 PUT 成功、Checkout 显示成功和模型流结束，各自只证明其中一步完成。

## 这次落地的状态规则

- **任务取消与进度**：取消在数据库写入时检查归属和可取消状态。若完成先赢，返回最新的已完成结果；若取消先赢，按写入返回的派发 ID 尽力取消队列。上一派发的回调不能覆盖当前进度。应用继续以同一 JSON 格式向客户端返回任务，重复取消也可安全读取终态。
- **上传与 AI 附件**：文件一选中就占用一个名额，并显示准备中；只有排队、失败或已取消的文件可以启动。每个文件同时只接受一个传输尝试的进度和结果。清空草稿、移除文件或卸载组件后，异步准备不能把旧文件重新加入队列。
- **付款回跳**：验证成功后只确认付款，当前权益请到账单页查看。回跳查询和 Webhook 之间存在时差；前端文案不把其中一次查询的成功解释成权益已生效。
- **故障与并发边界**。派发失败与对象删除失败都有各自的下次尝试时间。账号变更在写入事务内锁定并校验相关账号。AI 流订阅使用跨实例租约，列表用快照标识检测翻页期间的变化。付款查询按 checkout 隔离并有明确的重试状态，CLI 设备授权的等待和请求都受同一个截止时间约束。
- **保持状态所有权**：SQL 状态用条件写入或事务保护；客户端状态保留在拥有交互的组件和 hook；账务、模型调用和队列的交接仍按各自的重放规则恢复。无需引入通用状态机库或数据库迁移。

变更状态时，至少检查初始状态、失败或取消、并发赢家、刷新后恢复，以及客户端能够观察到的真实结果。只有同一业务状态跨多个所有者推进时，才增加共享合约。
